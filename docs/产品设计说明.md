## 1. 产品定位

IQE-Agent Platform 是一个**独立的 AI Agent 编排平台**:

- 平台内核只保留 **编排引擎 + 插件注册中心**;
- **Airflow、Qoder CN、Jenkins、Jira、Milvus 均为可选插件**,不是运行前提;
- 外部系统不可用时按文档 7.4 **自动降级**,演示不中断;
- 客户已有 Airflow 可启用插件;没有 Airflow 时平台自带编排器可直接运行。

**Demo 目标**:用 20–25 分钟向管理层证明“端到端自动化、可控人工卡点、知识库学习、平台独立性、成本 ROI”五点。

## 3. 插件体系

### 3.1 8 类插件(文档第 2 节)

| 类型 | 标识 | Demo 插件 | 生产可替换 |
|---|---|---|---|
| 输入源 | `input_source` | `mock_jenkins` | 真实 Jenkins Webhook |
| Agent | `agent` | 6 个 IQE Agent | 自定义 Agent |
| 知识库 | `knowledge_base` | `memory_vector_kb` | Milvus / PGVector |
| 工具 | `tool` | `jira_mock`、`jarvis_mock` | 真实 Jira / Jarvis |
| 编排引擎 | `orchestrator` | `memory_orchestrator`、`airflow_orchestrator` | Temporal / 自研 |
| LLM 提供商 | `llm_provider` | `mock_llm`、`qoder_cn` | GPT / 本地模型 |
| 事件总线 | `event_bus` | `memory_event_bus` | Kafka / RabbitMQ |
| 存储 | `storage` | `sqlite_storage` | PostgreSQL + S3 |

> 共 16 个插件实例(Agent 6 + 其他 10)。插件 ID、类型 ID 为 Demo 内部契约,文档未定义英文 ID【已确认 Q1/Q15】。

### 3.2 统一契约

所有插件继承 `BasePlugin`,提供:

- `plugin_id` / `display_name` / `description` / `plugin_type`
- `config_schema`:前端据此生成配置表单
- `dependencies`:声明依赖的插件类型(文档 2.1)
- `health() -> (bool, message)`
- `load()` / `unload()` / `state`
- `run_isolated()`:插件专属单线程执行器(文档 7.1)

编排引擎严格实现文档 3.2:

```python
async def start_pipeline(pipeline_def: dict) -> str
async def get_pipeline_status(run_id: str) -> dict
async def stop_pipeline(run_id: str) -> None
```

LLM 提供商严格实现文档 3.3:

```python
async def chat_completion(messages: list[dict], config: dict) -> dict
async def health() -> tuple[bool, str]
```

### 3.3 生命周期

注册 → 配置 → 健康检查 → 加载 → 运行 → 卸载,由 `PluginRegistry` 统一管理:

- 启动时扫描 `app/plugins/**`,自动注册插件类;
- 非 Agent 插件加载单例;Agent 插件**每次运行实例化**,避免运行间状态串扰;
- 配置持久化到 SQLite,密钥在 API 响应中脱敏为 `***`;
- 健康检查 2 秒超时(Q10),结果供前端展示与降级判断。

### 3.4 插件隔离

- 每个 Agent 在独立单线程执行器中运行(`asyncio.run`),异常被捕获并落 Trace / 死信;
- 单个插件崩溃不会终止平台进程;
- Agent 单次执行超时默认 120 秒(`IQE_AGENT_TIMEOUT_SECONDS`),超时后失败 Run 并写入死信;线程本身无法被 Python 强杀,超时只保证调用方及时失败(Q16 已确认)。

## 4. 标准事件信封(逐字对齐文档 3.1)

| 字段 | 类型 | 取值 / 约束 |
|---|---|---|
| `event_id` | string | UUID |
| `event_type` | enum | `monitor_alert` / `triage_result` / `repro_result` / `ticket_draft` / `review_result` / `report_item` |
| `source_agent` | string | 产生事件的插件 ID |
| `timestamp` | ISO 8601 | 统一 UTC,序列化为 `...Z` |
| `trace_id` | string | UUID,贯穿整条链路 |
| `confidence` | number | `0.0 ~ 1.0`,Pydantic 强校验 |
| `evidence_links` | string[] | 原始 Jenkins 工件、`kb://knowledge/{id}` |
| `status` | enum | `pending` / `passed` / `rejected` / `need_more_info` / `handover_human` |
| `model_info.model_loc` | enum | `local_strix_halo` / `cloud_qoder_cn` / `mock` |
| `model_info.model_name` | string | 模型名 |
| `model_info.latency_ms` | int ≥ 0 | Mock 模式为文档场景模拟耗时(Q12) |
| `model_info.cost_token` | int ≥ 0 | Token 成本 |
| `payload` | object | 业务字段;各 Agent 有 v0 必填字段(Q2 已确认) |

**校验策略**:额外字段一律拒绝;枚举/范围非法直接失败;Agent 输出 Schema 失败进入死信队列(文档 7.2)。Agent 输出还会校验 `payload_required_fields`,缺少必填字段同样按 Schema 失败处理。

## 5. 流水线设计

### 5.1 默认模板(逐字对齐文档 4.2)

`pipeline_id = iqe_validation_v1`,`orchestrator = airflow_orchestrator`。

| # | Agent | 输入源 | LLM | 知识库 | 工具 | 人工卡点 |
|---|---|---|---|---|---|---|
| 1 | monitor_agent | jenkins_webhook | qoder_cn | — | — | — |
| 2 | triage_agent | — | qoder_cn | memory_vector_kb | — | — |
| 3 | reproduction_agent | — | qoder_cn | — | jarvis_mock | — |
| 4 | ticket_agent | — | qoder_cn | — | jira_mock | — |
| 5 | reviewer_agent | — | qoder_cn | memory_vector_kb | — | ✅ |
| 6 | reporting_agent | — | qoder_cn | — | — | — |

> 文档 4.2 与场景 4 对“默认编排器”存在矛盾(C1):模板保留 Airflow 配置,但 Airflow 默认禁用,运行态降级为内置编排器;Trace 同时展示“配置编排器 / 实际编排器 / 降级原因”。

### 5.2 执行时序

```
推送 Mock Jenkins 事件
  → 创建 run + trace_id + 标准 monitor_alert
  → 解析编排器(Airflow 健康检查 / 降级内存编排器)
  → Monitor      归一化、去噪
  → Triage       日志分诊 + 知识库检索 + 置信度
  → Reproduction 调用 Jarvis 复现;环境/flaky 类拒绝
  → Ticket       调用 Mock Jira 生成草案(不写正式工单)
  → Reviewer     置信度 ≥ 0.7 自动通过;< 0.7 → handover_human
        ├─ 自动/人工通过 → 平台调用 Mock Jira 创建工单
        └─ 人工驳回 → run=rejected,不创建工单
  → Reporting    输出 TAT、工单号、知识命中
```

### 5.3 Agent 职责

| Agent | 输入 → 输出 | 关键逻辑 | 置信度 |
|---|---|---|---|
| Monitor | `monitor_alert` → `monitor_alert` | 归一化 job/build/log,初步噪声判断 | 0.99 |
| Triage | `monitor_alert` → `triage_result` | 关键词规则 + KB 检索;分类 product_bug/flaky/environment/driver_compatibility/unknown | 0.6 / 0.75 / 0.82 / 0.8 / 0.86 / KB 0.92 |
| Reproduction | `triage_result` → `repro_result` | Mock Jarvis;environment/flaky 不复现 → rejected | 沿链传递,不复现时 ≤ 0.55 |
| Ticket | `repro_result` → `ticket_draft` | 生成标题/描述/优先级;只调用 `create_draft` | 沿链传递 |
| Reviewer | `ticket_draft` → `review_result` | `< 0.7` → `handover_human`;`>= 0.7` → passed | 沿链传递 |
| Reporting | `review_result` → `report_item` | TAT、工单号、知识命中、摘要 | 沿链传递 |

> 置信度传递规则文档未定义(Q4):Demo 采用“沿链传递 Triage 置信度”,保证场景 2 的 0.6 不会被后续 Agent 抬高。

**payload v0 必填字段(Q2 已确认)**:

| Agent | 必填 payload 字段 |
|---|---|
| Monitor | `monitor_summary`、`noise` |
| Triage | `case_id`、`log_excerpt`、`category`、`root_cause` |
| Reproduction | `case_id`、`category`、`reproduced`、`attempts` |
| Ticket | `case_id`、`draft_id`、`ticket_title`、`ticket_description`、`priority` |
| Reviewer | `case_id`、`decision`、`threshold`、`ticket_title`、`review_summary` |
| Reporting | `case_id`、`tat_seconds`、`tat_source`、`summary` |

未列出的 payload 字段允许扩展,避免把未确认的外部输出直接拒绝;必填字段缺失会写入死信并失败 Run。

### 5.4 人工卡点

- 阶段配置 `human_gate: true` 仅出现在 Reviewer;
- 等待时 run 状态为 `waiting_human`,Trace 页面展示审批面板;
- 驳回原因由前端要求填写,后端记录到 `review_result.payload.review_reason`;
- 批准后平台创建 Mock Jira 工单,再执行 Reporting;
- `need_more_info` 枚举保留,但 Demo 不提供入口(Q22)。

### 5.5 知识库

- 内存向量库,启动时从 SQLite 重建索引;
- 分词 + 词频余弦;额外使用查询词覆盖率解决短查询稀释;
- 默认阈值 0.35、TopK 3(可配置,Q7);
- **Reviewer 阶段到达后**允许标记入库(包括 0.75 自动通过,解决文档矛盾 C2);
- 入库内容结构化保存:标题、日志摘要(`content`)、Triage 结论(`summary`)、根因(`root_cause`)、分类;检索只用标题/日志计分,结论不参与相似度;
- 同一 trace 幂等,不重复入库;
- 命中后 Triage 置信度 0.92、模拟耗时 30 秒(文档场景 3)。

### 5.6 Agent System Prompt

- 6 个 Agent 均有可配置的 `system_prompt`,默认模板集中在 `backend/app/plugins/agents/prompts.py`,版本 `v1.0.0`;
- 覆盖优先级:**阶段级 > 插件级 > 内置默认**;
  - 插件级:插件管理 → Agent 插件 → 配置,持久化到 `plugin_state`;
  - 阶段级:流水线画布 → 选中阶段 → System Prompt,持久化到 `pipelines.definition_json`;
- 阶段级留空表示不覆盖;插件级 Prompt 不允许为空,最长 12000 字符;
- 默认模板包含角色、输入字段、输出 JSON Schema、边界规则与一个 few-shot 示例;
- Agent 输出事件的 payload 增加 `prompt_version / prompt_source / prompt_hash`,其中 `prompt_source` 为 `default / plugin / stage`,便于 Trace 审计;
- Mock LLM 仍按任务规则运行,不依赖 Prompt 内容;真实 Qoder CN 会直接使用最终 Prompt。

## 6. Mock 降级设计(文档 7.4)

| 真实服务 | 降级方案 | 触发条件 | 实现 |
|---|---|---|---|
| Airflow | `memory_orchestrator` | 插件禁用 / 未启用执行委托 / 未配置 / 健康检查失败 / 触发异常 | 每次运行记录 `fallback_reason` |
| Qoder CN | `mock_llm` | 未配置凭据 / 不可达 / 超时 / LLM 调用异常 | Agent 内逐调用降级 |
| Jenkins | `mock_jenkins` | 无真实 Jenkins | 24 个预置案例 |
| Jira | `jira_mock` | 无真实 Jira | 草案 + 正式工单 |
| Milvus | `memory_vector_kb` | 无真实向量库 | SQLite 持久化 + 内存索引 |

- 降级不改变事件信封与流水线顺序;
- Trace 页面展示降级原因,避免把“降级成功”误认为“真实系统调用成功”;
- Airflow 插件新增 `delegate_execution`(默认 `false`):未显式开启执行委托时直接使用内置编排器,避免触发 DAG 后因无回调而挂起;插件同时暴露 `capabilities.agent_callback = false`;
- 健康检查 2 秒、外部调用默认 10 秒,均可配置(Q10 已确认)。

## 14. 已知限制

1. Airflow 真实 DAG 执行与回调未实现(Q8/C3):`delegate_execution` 默认 false,未开启时使用内置编排器;真实委托需确认 DAG/回调契约。
2. Qoder CN 未接入真实凭据(Q9):按 OpenAI 兼容接口预留,演示使用 Mock LLM。
3. 无登录/租户/RBAC/审计(Q13):仅支持可选的静态 Bearer Token,生产需接入统一身份与审计。
4. 插件隔离为线程级(Q16):单线程执行器 + 超时;生产建议进程/容器级隔离。
5. 模拟指标非真实墙钟(Q12):Trace、仪表盘、实验面板均标注来源,汇报时必须说明。
6. Mark-to-KB 在自动通过后仍开放:已确认用于复现场景 3(C2),产品化可按需收紧为仅人工卡点开放。
7. 并发上限与 Run 状态保存在进程内(Q21):多实例部署需改用分布式编排器与共享存储。
8. Prompt 治理为 Demo 级:支持版本/哈希审计与两级覆盖,但尚无审批流、A/B 测试与 RBAC;生产化需接入 Prompt 仓库与发布流程。
