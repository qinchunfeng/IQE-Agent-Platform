## C. 已按文档明确执行、无需确认的基线

1. **事件信封**(3.1):字段名、`event_type` 6 值、`status` 5 值、`model_loc` 3 值、`confidence` 0.0–1.0,全部用 Pydantic 强校验;额外字段拒绝。
2. **8 类插件**(第 2 节):输入源、Agent、知识库、工具、编排引擎、LLM 提供商、事件总线、存储。
3. **6 个 Agent**(4.2):`monitor_agent`、`triage_agent`、`reproduction_agent`、`ticket_agent`、`reviewer_agent`、`reporting_agent`,按文档顺序串行。
4. **默认阈值**(7.2):0.7;“低于阈值”才转人工,边界值自动通过。
5. **Mock 降级矩阵**(7.4):Airflow→内存编排器;Qoder CN→Mock LLM;真实 Jenkins→Mock Jenkins;真实 Jira→Mock Jira;Milvus→内存向量库。
6. **插件隔离**(7.1):每个插件独立单线程执行器,异常捕获,单插件崩溃不终止进程。
7. **端口**(0.4):前端 3200、后端 8000、Airflow 18080;均经本机绑定测试确认空闲。
8. **演示场景**(第 6 节):5 个场景作为前端操作入口与验收脚本。
9. **验收标准**(第 8 节):插件加载、流水线流转、Trace、低置信度人工卡点、审批、知识库、实验面板。

## H. 飞书通知实现基线(2026-11-03,Q26)

文档没有定义通知渠道。按“Run 结束后向指定群或个人发送报告”的目标,先实现
`feishu_notifier` 工具插件,外部飞书契约采用官方公开 API,无需用户再次提供平台侧规范。

| 项 | 实现基线 |
|---|---|
| 发送方式 | `webhook`:群自定义机器人;`app`:自建应用 tenant_access_token,可按 `chat_id/open_id/email/user_id` 发群或个人 |
| 触发时机 | `completed / rejected / failed / stopped`;`waiting_human` 默认关闭,可在插件配置开启 |
| 卡片内容 | 状态、案例、分类、置信度、工单号、TAT 及来源、输入源、编排器、失败/驳回原因、Agent 链路、“查看 Trace”按钮 |
| 幂等 | `run_notifications(run_id, plugin_id, status)` 唯一约束;同一 Run 的同一状态只发送一次 |
| 重试 | HTTP 429/5xx 与飞书 token 失效码重试,默认 2 次、间隔 1 秒;4xx 与业务参数错误不重试 |
| 失败隔离 | 投递异步执行;失败写 `run_notifications.state=failed`,不影响 Run 终态 |
| 安全 | `webhook_url`、`app_secret` 为 secret 字段,响应/日志脱敏;错误信息只含 HTTP 状态码与飞书 code |
| 查询状态 | `GET /api/runs/{run_id}/notifications` |

仍需使用者提供的外部信息(不写入仓库):

1. 群自定义机器人的 Webhook URL;或
2. 飞书自建应用的 `app_id / app_secret`、已开通 `im:message:send_as_bot` 权限、目标 `chat_id/open_id/email/user_id`。

> 本实现不修改飞书后台配置,也不在健康检查时发送测试消息;插件默认禁用,需人工配置并启用。
