## 4. 五个演示场景

### 场景 1:端到端自动化(约 3 分钟)

1. 仪表盘点击 **“推送模拟 CI 失败事件”**;
2. 页面自动进入 Trace 详情,等待流水线完成(模拟耗时,实际 1 秒内);
3. 讲解要点:
   - 7 个事件:Mock Jenkins + Monitor / Triage / Reproduction / Ticket / Reviewer / Reporting;
   - 链路置信度 86%;
   - 业务 TAT 8 分钟,指标下方标注 **“模拟业务耗时”**(文档场景 1 基线);
   - Reviewer 自动通过,Mock Jira 工单 `IQE-1`;
   - 顶部黄色提示:Airflow 未启用执行委托/已禁用,已降级到内置编排。
4. 返回仪表盘,可以看到今日指标与最近 Trace。

**话术**:从失败到有效工单只需要 8 分钟,人工平均 45 分钟,TAT 缩短约 80%。

### 场景 2:人工卡点(约 3 分钟)

1. 打开 **数据源** → **场景 2** → **“推送低置信度案例”**;
2. Trace 详情会停在 Reviewer:
   - 状态 `等待人工`;
   - 链路置信度 **60%**,低于阈值 0.7;
   - 工单显示“未创建”;
   - Reviewer 节点为琥珀色,Reporting 尚未执行。
3. 在审批框填写 **“证据不足”**,点击 **“驳回”**;
4. 状态变为“已驳回”,无工单,Reviewer 节点变红。

**可选**:再推一次低置信度案例,点击 **“批准并创建工单”**,会创建 Mock Jira 工单并执行 Reporting。

**话术**:Agent 不直接写 Jira,人工拥有最终决定权;驳回原因会写入 Trace。

### 场景 3:知识库加速(约 4 分钟)

1. 数据源 → **场景 3(A)** → **“推送案例 A”**(`IQE-CASE-017`);
2. 完成后的 Trace:
   - 置信度 75%;
   - Triage 耗时 **3.0 min**;
   - TAT 8 分钟;
3. 点击顶部 **“标记入库知识库”**,页面出现“已入库知识”卡片,其中包含日志摘要、Triage 根因与分类;
4. 点击 **“推送相似案例 B”**(或数据源 → 场景 3 B,`IQE-CASE-018`);
5. 对比案例 B:
   - 置信度 **92%**;
   - Triage 耗时 **30 秒**;
   - KB 命中“是”,证据中包含 `kb://knowledge/...`;
   - TAT **5 分 30 秒**;
6. 打开 **知识库**,搜索 `GPU driver crashed during device initialization`,可以看到案例 A,并显示相似度分数。

**话术**:知识库命中后,Triage 效率提升 6 倍,置信度从 0.75 提升到 0.92。

### 场景 4:平台独立性 / 自动降级(约 4 分钟)

1. 打开 **插件管理**:
   - 展示 8 类插件、16 个插件实例;
   - Airflow Orchestrator **已禁用**;
   - Qoder CN Cloud 显示红色“不可用 / 未配置 API URL”;
2. 打开 **流水线画布**:
   - 6 个 Agent 的蛇形编排;
   - 配置编排器为 Airflow;
   - 点击节点可查看 LLM / 知识库 / 工具 / 人工卡点配置;
3. 推送事件 → Trace 顶部显示:
   - 配置编排器:Airflow;
   - 实际编排器:内置编排引擎;
   - 降级原因:Airflow 已禁用;
4. 回到插件管理,点击 Airflow 的 **“已禁用”开关**:
   - 健康检查显示“Airflow 不可达: ConnectError”(本机未安装/未启动);
   - 打开 Airflow **配置**,确认 `delegate_execution` 默认关闭;保存后推送事件,Trace 降级原因为“Airflow 插件未启用执行委托,使用内置编排器”;
   - 若把 `delegate_execution` 打开再推送,Trace 降级原因为“Airflow 不可用(...)”;Demo 未实现回调契约,不建议在演示中打开。
5. 再次关闭 Airflow;
6. 可选:关闭 Qoder CN,推送事件,Trace 中 LLM 降级原因为“Qoder CN 已禁用”,模型调用仍为 Mock;
7. 讲解:平台不依赖 Airflow/Qoder CN,外部系统是可选增强。

> **注意**:文档未定义 Airflow DAG 回调契约(Q8),本次不宣称“Airflow 真实执行流水线”。场景 4 演示的是插件切换、健康检查、执行委托开关与降级能力。

### 场景 5:成本对比(约 3 分钟)

打开 **实验面板**:

| 指标 | Qoder CN Cloud | Mock Local | 人工 |
|---|---|---|---|
| TAT | 8 min | 12 min | 45 min |
| 单票成本 | ¥2.5 | ¥0.3 | — |
| 置信度 | 88% | 85% | — |

- 页面同时展示平台实测均值(来自已运行 Trace);
- “知识库效果”展示命中/未命中的置信度与 Triage 耗时;
- 页面明确标注:8/12/45 分钟为**文档基线**,Mock 模式耗时为**模拟业务耗时**,不是真实墙钟(Q12)。

**话术**:高频场景用本地、复杂场景用云端,混合策略可降低成本约 70%,质量损失小于 5%。

## 5. 插件配置演示

1. 插件管理 → 任选插件 → **“配置”**;
2. 表单按 `config_schema` 自动生成;
3. Qoder CN 可填写:
   - API URL(如本机 OpenAI 兼容代理,必须以 `http://` 或 `https://` 开头);
   - API Key(密码框,响应中脱敏为 `***`);
   - 模型名、超时;
4. Airflow 可填写:
   - URL(默认 `http://localhost:18080`,必须以 `http://` 或 `https://` 开头);
   - 用户名 / 密码(密码脱敏);
   - DAG ID 前缀、超时;
   - `delegate_execution`(默认关闭;开启前需自行提供 DAG 与回调,否则 Run 可能停在等待状态);
5. 内置编排引擎可配置 `max_concurrent_runs`(默认 8);
6. 保存后立即重新做健康检查。

**密钥规则**:保留 `***` 表示不修改;输入空字符串表示清除;新值才会覆盖。

### 5.1 可选 API Token(默认关闭)

本机演示不需要 Token。若需在非本机环境演示,启动前设置相同 Token:

```bash
# 后端
export IQE_API_TOKEN='replace-with-a-long-random-token'
./scripts/run_backend.sh

# 前端(另一个终端)
export VITE_API_TOKEN='replace-with-a-long-random-token'
./scripts/run_frontend.sh
```

设置后,除 `/api/health` 外的 `/api/*` 都需要 `Authorization: Bearer <token>`;前端会自动带上。不要在演示材料中记录真实 Token。

### 5.2 Agent System Prompt 配置

两级配置,优先级 **阶段级 > 插件级 > 内置默认**:

1. **插件级默认 Prompt**
   - 插件管理 → Agent 插件(如 Triage Agent) → **配置**;
   - 编辑 **System Prompt** 多行文本框;
   - 保存后,所有未做阶段覆盖的 Triage 阶段都会使用该 Prompt;
   - 留空或清空会被校验拒绝,如需恢复请重新填入默认模板。

2. **阶段级覆盖**
   - 流水线画布 → 点击某个 Agent 节点;
   - 右侧 **阶段配置** → 编辑 **System Prompt**;
   - 保存流水线定义后生效;留空表示使用插件级 Prompt;
   - 点击 **“清除阶段覆盖”** 可回退到插件级。

3. **审计**
   - 下一次 Run 的 Agent 事件 payload 中会出现:
     - `prompt_version`:默认模板版本,如 `v1.0.0`;
     - `prompt_source`:`default` / `plugin` / `stage`;
     - `prompt_hash`:最终 Prompt 的 SHA-256 前 12 位;
   - Trace 事件卡片会直接展示这三个字段。

> Mock LLM 按任务规则输出,不会因为修改 Prompt 而改变结果;Prompt 主要影响真实 Qoder CN。演示时可说明“Prompt 已版本化并可审计,当前 Mock 仍保证结果可重复”。

## 8. 常见问题

| 现象 | 排查 |
|---|---|
| 顶部显示“API 未连接” | 后端是否在 8000 启动;查看 `/tmp` 或终端日志;`curl http://127.0.0.1:8000/api/health` |
| 前端 3200 打不开 | 端口被占用:Vite 配置 `strictPort: true`;先停止占用进程 |
| 推送后无 Trace | 检查后端日志;确认 `mock_jenkins` 插件未禁用 |
| Qoder CN 红色“不可用” | 预期状态;未配置 API URL/Key 时使用 Mock LLM |
| Airflow 红色“不可达” | 预期状态;本机未启动 Airflow,启用后会降级到内置编排器 |
| 所有 API 返回 401 | 设置了 `IQE_API_TOKEN` 但请求未带 `Authorization: Bearer ...`;本机演示可取消该环境变量并重启后端 |
| Airflow 已启用但仍走内置编排 | 检查 `delegate_execution` 是否开启;默认关闭以避免触发后无回调挂起 |
| 仪表盘 TAT 标注“模拟业务耗时” | Mock 模式预期;真实墙钟与文档基线在页面分别标注,不要当作实测 |
| Reviewer 不暂停 | 只有置信度 < 0.7 才暂停;可推 `IQE-CASE-019` |
| 工单号不是 IQE-1 | 之前已有运行;执行重置脚本后重启 |
| 知识库搜索不到 | 先完成场景 3 A 的“标记入库”;阈值 0.35,可用完整日志搜索 |
| 修改了阈值/配置不生效 | 配置保存在 SQLite;刷新插件页;Agent 每次运行读取最新配置 |
| 修改 Prompt 后 Mock 输出没变 | 预期:Mock LLM 按任务规则输出;Prompt 会写入事件审计字段,真实 Qoder CN 才会使用 |
| 阶段 Prompt 没生效 | 检查画布是否保存;阶段级 > 插件级;留空阶段 Prompt 会回退到插件配置 |
