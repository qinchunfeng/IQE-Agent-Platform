## 3. 首次打开时应该看到什么

- 顶部“API 已连接”;
- 仪表盘“今日待处理失败:0”,其他指标为 0;
- 仪表盘显示“今日口径”(服务端本地时区)与 TAT 来源标签;
- 数据源页显示 **Airflow 实时监控** 卡片(未配置时提示未启用/不可达)与 **外部运行/错误日志** 上传卡片;

- 插件管理中 **Qoder CN Cloud 显示“不可用 / 未配置 API URL”**,这是预期状态,平台会自动用 Mock LLM。

## 4. 五个演示场景

### 场景 1:端到端自动化(约 3 分钟)

1. 仪表盘点击 **“推送模拟 CI 失败事件”**;
2. 页面自动进入 Trace 详情,等待流水线完成(模拟耗时,实际 1 秒内);
   - 仪表盘“平台流水线”支持动态高亮当前 Agent,点击节点可在右侧抽屉查看输入/处理/输出;
   - “2 处理”展示本次运行实际使用的 System Prompt 快照、来源(阶段/插件/默认)与字符数;
   - 从仪表盘推送会直接进入 Trace 页;如需观察高亮,请从数据源页推送后立即返回仪表盘(真实 LLM 阶段约 15 秒);
   - “运行实例”下拉可切换历史或运行中的 Run;未执行阶段显示“尚未执行”;
3. 讲解要点:
   - 7 个事件:Mock Jenkins + Monitor / Triage / Reproduction / Ticket / Reviewer / Reporting;
   - 链路置信度 86%;
   - 业务 TAT 8 分钟,指标下方标注 **“模拟业务耗时”**(文档场景 1 基线);
   - Reviewer 自动通过,Mock Jira 工单 `IQE-1`;
   - Trace 顶部“输入源”显示 `Jenkins / Mock Jenkins`,编排器为内置编排引擎;
4. 返回仪表盘,可以看到今日指标与最近 Trace。

**话术**:从失败到有效工单只需要 8 分钟,人工平均 45 分钟,TAT 缩短约 80%。

### 场景 2:人工卡点(约 3 分钟)

1. 打开 **数据源** → **场景 2** → **“推送低置信度案例”**;
2. Trace 详情会停在 Reviewer:
   - 状态 `等待人工`;
   - 链路置信度 **60%**,低于阈值 0.7;
   - 工单显示“未创建”;
   - Reviewer 节点为琥珀色,Reporting 尚未执行。
3. 在审批框填写 **“证据不足”**,点击 **“驳回”**;
4. 状态变为“已驳回”,无工单,Reviewer 节点变红。

**可选**:再推一次低置信度案例,点击 **“批准并创建工单”**,会创建 Mock Jira 工单并执行 Reporting。

**话术**:Agent 不直接写 Jira,人工拥有最终决定权;驳回原因会写入 Trace。

### 场景 3:知识库加速(约 4 分钟)

1. 数据源 → **场景 3(A)** → **“推送案例 A”**(`IQE-CASE-017`);
2. 完成后的 Trace:
   - 置信度 75%;
   - Triage 耗时 **3.0 min**;
   - TAT 8 分钟;
3. 点击顶部 **“标记入库知识库”**,页面出现“已入库知识”卡片,其中包含日志摘要、Triage 根因与分类;
4. 点击 **“推送相似案例 B”**(或数据源 → 场景 3 B,`IQE-CASE-018`);
5. 对比案例 B:
   - 置信度 **92%**;
   - Triage 耗时 **30 秒**;
   - KB 命中“是”,证据中包含 `kb://knowledge/...`;
   - TAT **5 分 30 秒**;
6. 打开 **知识库**,搜索 `GPU driver crashed during device initialization`,可以看到案例 A,并显示相似度分数。

**话术**:知识库命中后,Triage 效率提升 6 倍,置信度从 0.75 提升到 0.92。

### 场景 4:平台独立性 / 真实输入源(约 4 分钟)

1. 打开 **插件管理**:
   - 展示 8 类插件、18 个插件实例;
   - 编排器只有内置编排引擎;
   - **Airflow 输入源**:已启用时显示健康状态与 DAG 数;未配置时显示“不可用”;
   - Qoder CN Cloud:已配置真实代理时显示绿色“Qoder CN 可访问(HTTP 200)”,否则红色“不可用”,平台自动用 Mock LLM;
2. 打开 **流水线画布**:
   - 左侧输入源列表可看到 Jenkins 与 Airflow;右侧 6 个 Agent 的蛇形编排;
   - 点击节点可查看 LLM / 知识库 / 工具 / 人工卡点配置;编排器固定为内置引擎;
3. 打开 **数据源 → Airflow 实时监控**:
   - 点击 **“立即检查(回看 7 天)”**;
   - 若有失败 Run,页面自动进入新 Trace,Trace 顶部“输入源”为“Airflow 输入源”;
   - 相同 `dag_id:dag_run_id` 已处理过时不会重复触发;
4. 在插件管理中临时禁用 Airflow 输入源,再点击“立即检查”,提示输入源不可用/未启用;
5. 外部日志:在 **外部运行/错误日志** 卡片填写文件名与日志内容,点击 **“上传并触发”**,同样会创建 Trace;
6. 可选:关闭 Qoder CN,推送事件,Trace 中 LLM 降级原因为“Qoder CN 已禁用”,模型调用仍为 Mock;
7. 讲解:平台不依赖 Airflow/Jenkins/Qoder CN,外部系统是可选增强。

> **注意**:v2.4 起 Airflow 不承担编排职责,平台只监控其失败 Run 并触发 Agent 流水线;不再宣称“Airflow 真实执行 Agent 流水线”。

### 场景 5:成本对比(约 3 分钟)

打开 **实验面板**:

| 指标 | Qoder CN Cloud | Mock Local | 人工 |
|---|---|---|---|
| TAT | 8 min | 12 min | 45 min |
| 单票成本 | ¥2.5 | ¥0.3 | — |
| 置信度 | 88% | 85% | — |

- 页面同时展示平台实测均值(来自已运行 Trace);
- “知识库效果”展示命中/未命中的置信度与 Triage 耗时;
- 页面明确标注:8/12/45 分钟为**文档基线**,Mock 模式耗时为**模拟业务耗时**,不是真实墙钟(Q12)。

**话术**:高频场景用本地、复杂场景用云端,混合策略可降低成本约 70%,质量损失小于 5%。

## 5. 插件配置演示

1. 插件管理 → 任选插件 → **“配置”**;
2. 表单按 `config_schema` 自动生成;
3. Qoder CN 可填写:
   - API URL(如本机 OpenAI 兼容代理,必须以 `http://` 或 `https://` 开头);
   - API Key(密码框,响应中脱敏为 `***`);
   - 模型名、超时;
4. Airflow 输入源可填写:
   - `api_url`(如 `http://airflow.example.com:8080`,必须以 `http://` 或 `https://` 开头);
   - 用户名 / 密码(密码脱敏);
   - `dag_ids`:**留空 = 监控全部 DAG;非空 = 仅监控列出的 DAG**(逗号/换行分隔,如 `test_flash_attention_flow`);
   - `api_version`(默认 `auto`:优先 Airflow 3 REST v2,失败回退 v1);
   - 轮询间隔、回看窗口、单轮最大事件数/任务数、超时;
5. 内置编排引擎可配置 `max_concurrent_runs`(默认 8);
6. 保存后立即重新做健康检查。

**密钥规则**:保留 `***` 表示不修改;输入空字符串表示清除;新值才会覆盖。

### 5.3 接入真实 Airflow(测试环境)

1. 插件管理 → **输入源 → Airflow 输入源**,点击“配置”;
2. 填写:
   - `api_url`:`http://airflow.example.com:8080`
   - `username` / `password`:按测试环境实际账号填写(**不要写入文档或仓库**)
   - `dag_ids`:`test_flash_attention_flow`(留空则监控全部 19 个 DAG)
   - `api_version`:`auto`
3. 保存后健康状态应显示 `Airflow 3.3.1 可访问,发现 19 个 DAG`;
4. 打开 **数据源 → Airflow 实时监控**,确认 DAG 列表中包含目标 DAG;
5. 点击 **“立即检查(回看 7 天)”**;若存在失败 Run,会自动创建 Trace 并启动 6 Agent 流水线;
6. Trace 顶部可核对“输入源:Airflow 输入源”与失败 Run 的证据链接。

> Airflow 3 使用 JWT(`POST /auth/token`),不是 Basic Auth;平台会自动探测并处理。**不要在演示材料中记录真实密码**;本指南中的测试凭据仅用于本机验收,不应提交到公共仓库。
>
> 同一个 `dag_id:dag_run_id` 只会触发一次;如需重复演示,请在 Airflow 侧产生新的失败 Run。

### 5.4 接入真实 Qoder CN(测试环境)

1. 确认本机代理运行在 `http://127.0.0.1:3000/v1`(OpenAI 兼容);
2. 插件管理 → **LLM 提供商 → Qoder CN**,点击“配置”;
3. 填写:
   - `api_url`:`http://127.0.0.1:3000/v1`
   - `api_key`:代理的客户端 Key(即代理自身 `.env` 中的 `PROXY_API_KEY`,通常为 `sk-...`)
   - `model`:`DeepSeek-Flash`
   - `timeout_seconds`:`120`
4. 保存后健康状态应显示 `Qoder CN 可访问(HTTP 200)`;
5. 推送 Mock 案例 `IQE-CASE-001`,Trace 中每个 Agent 应显示模型 `DeepSeek-Flash`、`cloud_qoder_cn`。

> **重要**:用户提供的 `pt-...` 是 Qoder CN 的**上游个人访问令牌**,不是代理的客户端 Key;直接填入会被代理拒绝(HTTP 401)。请使用代理已配置的 `PROXY_API_KEY`。**不要修改代理或外部平台配置**;如需变更代理 Key,先与维护人确认。

### 5.5 画布自定义输入源与 Agent

1. 打开 **流水线画布**;
2. 左侧“输入源”区:
   - 点击 **“添加输入源”**,选择 Airflow / Mock Jenkins / 外部日志文件;
   - 可启停、删除;同一插件可添加多个实例;
3. 右侧“Agent 阶段”区:
   - 点击 **“添加 Agent”**,选择任一 Agent;允许重复添加;
   - 通过阶段序号/上下移动调整顺序;删除后自动重排;
   - 点击节点编辑 LLM / 知识库 / 工具 / 人工卡点 / System Prompt;
4. 点击 **“保存流水线”**;下一次 Run 使用新定义,不影响运行中的 Run;
5. Trace 通过 `source_agent` 顺序映射阶段,重复 Agent 不会串位。

### 5.1 可选 API Token(默认关闭)

本机演示不需要 Token。若需在非本机环境演示,启动前设置相同 Token:

```bash
# 后端
export IQE_API_TOKEN='replace-with-a-long-random-token'
./scripts/run_backend.sh

# 前端(另一个终端)
export VITE_API_TOKEN='replace-with-a-long-random-token'
./scripts/run_frontend.sh
```

设置后,除 `/api/health` 外的 `/api/*` 都需要 `Authorization: Bearer <token>`;前端会自动带上。不要在演示材料中记录真实 Token。

### 5.2 Agent System Prompt 配置

两级配置,优先级 **阶段级 > 插件级 > 内置默认**:

1. **插件级默认 Prompt**
   - 插件管理 → Agent 插件(如 Triage Agent) → **配置**;
   - 编辑 **System Prompt** 多行文本框;
   - 保存后,所有未做阶段覆盖的 Triage 阶段都会使用该 Prompt;
   - 留空或清空会被校验拒绝,如需恢复请重新填入默认模板。

2. **阶段级覆盖**
   - 流水线画布 → 点击某个 Agent 节点;
   - 右侧 **阶段配置** → 编辑 **System Prompt**;
   - 保存流水线定义后生效;留空表示使用插件级 Prompt;
   - 点击 **“清除阶段覆盖”** 可回退到插件级。

3. **审计**
   - 下一次 Run 的 Agent 事件 payload 中会出现:
     - `prompt_version`:默认模板版本,如 `v1.0.0`;
     - `prompt_source`:`default` / `plugin` / `stage`;
     - `prompt_hash`:最终 Prompt 的 SHA-256 前 12 位;
   - Trace 事件卡片会直接展示这三个字段。

> Mock LLM 按任务规则输出,不会因为修改 Prompt 而改变结果;Prompt 主要影响真实 Qoder CN。演示时可说明“Prompt 已版本化并可审计,当前 Mock 仍保证结果可重复”。

### 5.6 飞书结束通知(默认禁用)

平台可在 Run 完成、驳回或失败后,向指定飞书群或个人发送汇总卡片。插件管理中的“飞书通知”默认禁用,不会自动向外部发送消息。

**方式 A:群自定义机器人(Webhook)**

1. 在飞书目标群中创建“自定义机器人”,复制 Webhook URL;此操作需在飞书侧由管理员完成,平台不会修改群配置;
2. 插件管理 → **工具 → 飞书通知 → 配置**;
3. `mode=webhook`,填写 `webhook_url`;
4. 确认“完成时通知 / 驳回时通知 / 失败时通知”按需开启,保存并启用插件。

**方式 B:自建应用(群或个人)**

1. 飞书开放平台创建自建应用,开通 `im:message:send_as_bot` 权限并发布;
2. 获取 `app_id / app_secret`,以及目标群 `chat_id` 或个人 `open_id / email / user_id`;
3. 插件配置中设置 `mode=app`,填写上述字段,并选择对应的 `receive_id_type`;
4. 保存并启用。

**验证与排查**

- 推送 `IQE-CASE-001` 并等待完成后,可查询投递状态:
  ```bash
  curl -s http://127.0.0.1:8000/api/runs/<run_id>/notifications
  ```
- `state=sent` 表示发送成功;`failed` 的 `error` 只包含 HTTP 状态码或飞书业务 code,不包含 URL/密钥;
- 健康检查只校验配置完整性,**不会发送测试消息**;健康显示“已配置”不等于飞书已成功投递;
- “待人工时通知 / 停止时通知”默认关闭;同一 Run 的同一状态只发送一次;
- `dashboard_url` 默认 `http://127.0.0.1:3200`,若收件人不在本机,需要改为可访问的平台前端地址,否则卡片“查看 Trace”按钮不可达;
- Webhook URL、`app_secret` 在 API 响应中显示为 `***`,保留 `***` 保存表示不修改;真实凭据不要写入文档、截图或公共仓库。

## 8. 常见问题

| 现象 | 排查 |
|---|---|
| 顶部显示“API 未连接” | 后端是否在 8000 启动;查看 `/tmp` 或终端日志;`curl http://127.0.0.1:8000/api/health` |
| 前端 3200 打不开 | 端口被占用:Vite 配置 `strictPort: true`;先停止占用进程 |
| 推送后无 Trace | 检查后端日志;确认对应输入源插件未禁用(如 `mock_jenkins`) |
| Qoder CN 红色“不可用” | 未配置 API URL/Key 时使用 Mock LLM;已配置时检查代理是否运行、Key 是否为 `PROXY_API_KEY` |
| Qoder CN 返回 401 | 误把上游 `pt-...` 令牌当作代理客户端 Key;改用代理的 `PROXY_API_KEY`,不要修改代理配置 |
| Airflow 红色“不可达” | 检查 `api_url`、网络连通性与账号密码;Airflow 3 需支持 `/auth/token`;不可达只影响该输入源 |
| 点击“立即检查”没有新 Trace | 该 `dag_id:dag_run_id` 已处理过(幂等);请在 Airflow 产生新的失败 Run 后再试 |
| Airflow 事件触发但 Reproduction 拒绝 | 正常业务分支:失败被判定为环境问题,不建单;用 Mock `IQE-CASE-001` 演示完整建单 |
| 所有 API 返回 401 | 设置了 `IQE_API_TOKEN` 但请求未带 `Authorization: Bearer ...`;本机演示可取消该环境变量并重启后端 |
| 仪表盘 TAT 标注“模拟业务耗时” | Mock 模式预期;真实墙钟与文档基线在页面分别标注,不要当作实测 |
| Reviewer 不暂停 | 只有置信度 < 0.7 才暂停;可推 `IQE-CASE-019` |
| 工单号不是 IQE-1 | 之前已有运行;执行重置脚本后重启 |
| 知识库搜索不到 | 先完成场景 3 A 的“标记入库”;阈值 0.35,可用完整日志搜索 |
| 修改了阈值/配置不生效 | 配置保存在 SQLite;刷新插件页;Agent 每次运行读取最新配置 |
| 修改 Prompt 后 Mock 输出没变 | 预期:Mock LLM 按任务规则输出;Prompt 会写入事件审计字段,真实 Qoder CN 才会使用 |
| 阶段 Prompt 没生效 | 检查画布是否保存;阶段级 > 插件级;留空阶段 Prompt 会回退到插件配置 |
| 飞书通知没有发出 | 插件默认禁用;确认已启用、模式/凭据/接收者完整、目标状态通知已开启;查 `/api/runs/<run_id>/notifications` |
| 飞书插件健康显示“已配置”但收不到消息 | 健康检查不发送测试消息;检查飞书应用权限/机器人入群、网络与投递记录中的错误码 |
